# Система диалога агента EXANTE

## Описание

Добавлена система для симуляции диалога с потенциальным клиентом брокера EXANTE. Агент играет роль **Андрея Соколова** - владельца компании в сфере digital-маркетинга, которого заинтересовала возможность открытия счёта.

## Архитектура

### Новые компоненты

1. **`backend/app/agent_service.py`** - основной сервис агента
   - `AgentService` - класс для управления диалогом
   - `AgentResponse` - структура для ответов агента с полями:
     - `reply` - ответ клиента (видно Relationship Manager)
     - `intetions` - внутреннее состояние (скрыто)
     - `state` - текущая стадия клиента
     - `trust` - доверие к продавцу (0-100)
     - `purchase_probability` - вероятность покупки (0-100)
     - `done` - завершена ли беседа

2. **Обновлены схемы** (`backend/app/schemas.py`)
   - `AgentResponseData` - Pydantic модель ответа агента
   - `AgentRequest` - запрос к агенту
   - `AgentTurnResponse` - полный ответ с историей чата

3. **Обновлены API endpoints** (`backend/app/api.py`)
   - `POST /api/v1/agent/chat` - основной endpoint для взаимодействия с агентом

4. **Обновлена инициализация** (`backend/main.py`)
   - Агент-сервис инициализируется при запуске приложения

## Сценарий клиента

### Персона
- **Имя**: Андрей Соколов
- **Возраст**: 39 лет
- **Профессия**: владелец компании digital-маркетинга
- **Регион**: Европа
- **Инвестиционный капитал**: ~€60,000
- **Потенциальный депозит**: €10,000–€20,000

### Финансовый опыт
- Инвестирует ~4 года
- Совершает 1-4 сделки в месяц
- Понимает: акции, ETF, диверсификацию, валютный риск
- Слышал о: опционы, фьючерсы, margin trading (но не использует)
- НЕ использует: алгоритмическую торговлю, API, управление чужими активами

### Текущий портфель
- ~€25,000 - ETF американские
- ~€10,000 - отдельные акции
- ~€10,000 - ETF европейские  
- €15,000 - наличные
- Использует недорогого европейского retail-брокера

### Ключевой вопрос для продавца
Агент ожидает ответа на вопрос:
> "Почему мне стоит положить €10,000+ в EXANTE, если мой текущий брокер нормально работает?"

### Состояния (state)
- `curious` - просто изучает
- `considering` - допускает возможность
- `interested` - обнаружена потребность
- `evaluating` - хочет конкретные детали
- `ready_for_next_step` - готов к действию
- `ready_to_fund` - готов к депозиту
- `rejected` - решил отказаться

### Доверие (trust, 0-100)
**Повышается при:**
- Хорошие discovery-вопросы
- Внимательность к ответам
- Конкретность
- Честность о цене
- Признание ограничений

**Снижается при:**
- Игнорирование ответов
- Стандартная презентация
- Давление и спешка
- Уклонение от вопросов о комиссиях
- Скрытие ограничений

**Критические ошибки** (мгновенно снижают trust):
- "Вы точно заработаете"
- "Здесь невозможно потерять"
- "Капитал полностью гарантирован"
- "Переведите сегодня, завтра измениться"

### Типичные возражения

1. **Количество инструментов**
   - Агент: "Но я использую максимум 20. Что мне дают остальные 2млн?"
   
2. **Стоимость**
   - Агент: "Почему платить больше за то же самое?"
   - Ready платить больше за понятную ценность

3. **Минимальный депозит**
   - Агент: "€10k доступны, но это значимая сумма"
   
4. **Безопасность**
   - Вопросы: регулирование, хранение активов, segregation
   - Формулирует естественно: "А если с компанией что-то случится?"

5. **Сложность**
   - Агент: "Я не хочу сидеть перед 6 графиками весь день"

## Интеграция с фронтенд

### Пример JavaScript

```javascript
async function askAgent(message, chatId) {
  const response = await fetch('/api/v1/agent/chat', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({
      message: message,
      chat_id: chatId
    })
  });
  
  const data = await response.json();
  
  // Агент видит только reply
  console.log('Ответ клиента:', data.agent_response.reply);
  
  // Продавец может видеть полную информацию о состоянии
  console.log('Доверие:', data.agent_response.trust);
  console.log('Вероятность покупки:', data.agent_response.purchase_probability);
  console.log('Состояние:', data.agent_response.state);
  
  return data;
}
```

## Сохранение истории

Все сообщения сохраняются в SQLite:
- История полностью восстанавливается по `chat_id`
- Можно получить историю через `/api/v1/chats/{chat_id}/messages`
- Агент видит предыдущие сообщения для контекста

## Безопасность

### Что видит Relationship Manager (через API)
- Только `reply` (ответ клиента)
- История предыдущих обменов (только реплики)

### Что скрыто
- `intetions` - внутренние мысли
- `trust` - доверие к RM
- `purchase_probability` - вероятность покупки
- `state` - текущее состояние

## Расширение функционала

Система спроектирована для расширения:

1. **Добавить новые сценарии** - создать класс-наследник от `AgentService`
2. **Изменить персону** - отредактировать `_get_agent_system_prompt()`
3. **Добавить метрики** - расширить `AgentResponse`
4. **Интеграция с аналитикой** - примечание в `metadata`
